# Fcam pro — 設計概要と実装状況（v2.5.2）

## v2.5.2 の変更点（通常モードの没入型縦プレビュー）

- **モード別プレビュー方針**: スマホ縦画面の通常PHOTO／VIDEO／SLOWMOは、コンパクト操作デッキ以外の残り高をすべてプレビューへ割り当てる。選択中の4:3／16:9は撮影・保存解像度に維持し、通常プレビューだけを`FILL_CENTER`で中央クロップする。
- **Proの互換性**: Proは従来どおり4:3／16:9の横長固定枠を維持し、撮影情報・設定デッキ・プロファイル領域を侵食しない。OTHERS／PANORAMAも専用操作を表示できる固定枠のままとする。
- **操作の連続性**: レンズ選択ピルを通常プレビュー下端へ重ね、旧中央余白を廃止。単一`PreviewView`とCameraX bindは変更せず、Composeの親コンテナ制約だけを切り替える。
- versionCode 13 / versionName 2.5.2。Xperia 1で通常↔Proの反復切替、PHOTO↔OTHERS、縦横回転を確認。29テスト、Lint、正式鍵署名Releaseが成功。

## v2.5.1 の変更点（通常プレビュー配置・高密度UI・BG録画安全化）

- **通常プレビューの所有関係**: 通常モードのプレビューを別の全画面レイヤーとして置かず、`CameraOverlay`のpreview content slotとして構成。横は固定アスペクトのプレビューと操作デッキを兄弟要素として隙間なく並べ、縦はプレビューから操作群へ自然に接続する。
- **縦横で同じ形**: 明示した4:3／16:9枠内は`PreviewView.ScaleType.FILL_CENTER`とし、回転後のstreamが狭い縦長TextureViewへ縮むのを防止。縦画面でも横長のプレビュー枠を維持し、撮影・表示の下方向だけを更新する。
- **Sony系の操作密度**: 主要操作を48dp以上の正方形タイルへ統一。3dp角と境界線で制御単位を明確化し、選択は色と枠の両方で示す。二重safe-insetと旧floating panel由来の空白を除去した。
- **BG録画の状態機械**: bind完了まで`startPending`を保持し二重開始を拒否。Home・画面オフ・履歴削除後もforeground recordingを継続し、停止時は`VideoRecordEvent.Finalize`を待ってからunbindする。`running`は解放完了までtrueなのでActivityカメラとの再bind競合を起こさない。Finalize待ちは5秒でfallbackする。
- **ライフサイクル**: UIの主要`StateFlow`を`collectAsStateWithLifecycle`で購読し、非表示時の不要なCompose更新を抑制。
- versionCode 12 / versionName 2.5.1。Xperia 1で通常↔Pro 12回、縦横、4:3／16:9、14分16秒と20.4秒のBG録画、画面オフ・Home・履歴削除・Finalize後のpreview復帰を確認。28テスト、Lint、正式鍵署名Releaseが成功。

## v2.5.0 の変更点（プレビュー所有権・固定アスペクト・編集可能モードバー・カラープロファイル）

- **単一プレビュー所有権**: `PreviewView` を画面向きから独立した単一インスタンスとし、`movableContentOf` 内の唯一の `AndroidView` が通常／プロ／縦／横の配置間を移動する。向き変更は Preview / ImageCapture / VideoCapture の `targetRotation` とレイアウトだけを更新し、カメラ bind や Surface の再生成を起こさない。
- **固定アスペクト**: `FIT_CENTER` と `BoxWithConstraints` で、選択した 4:3 / 16:9 の矩形を幅・高さの両制約内へ内接させる。端末の向きによってプレビュー矩形を回転・変形せず、UI の配置と撮影時の下方向だけを切り替える。
- **モードバー編集**: 既定を PHOTO / VIDEO / OTHERS とし、SLOWMO / PANORAMA は OTHERS 内へ移動。隠れたモードは下ドラッグでバーへ追加、バー上ではドラッグ並び替えと上ドラッグによる格納ができ、`AppSettings` へ永続化する。OTHERS は常に残して復帰経路を保証する。
- **プロファイルドック**: 設定部下の空き領域へフロッピーアイコンだけの保存ボタンと色付きプロファイルボタンを常設。新規／上書き選択、6色、新規名検証、タップ適用、長押しドラッグ並び替え、追加保持による削除確認を提供する。選択状態は3dp白枠も併用して色覚だけに依存しない。
- **互換性**: Room v3 へ `colorArgb` / `sortOrder` を非null既定値付きで追加する明示 migration を実装。既存 v2 プロファイル、applicationId、minSdk 24、MediaStore 保存先、外部カメラ Intent は維持。
- **検証**: 単体テスト 28 件、Android lint、debug / 署名 release build。Xperia 1 SOV40 で Pro↔通常12往復、縦横9回、4:3 / 16:9、モード追加・永続・削除、プロファイル新規・色・上書き・削除、静止画、3秒動画を確認。全ストレス中で PID 維持、FATAL / PreviewView 親競合 / bind 失敗なし。

- **アクセシビリティ／翻訳**: タッチ対象を 58dp、境界線を黒背景比 3:1 以上、選択色をオレンジへ統一。新規文言と contentDescription を英語既定／日本語で 164 件ずつ完全一致させた。

## レンズ認識の修正・bindフォールバック・手動パネル堅牢化（未リリース分、Galaxy報告対応）

- **非BC除外の緩和**: 従来は `BACKWARD_COMPATIBLE` のないカメラを一律除外していたため、Galaxy系の単独望遠論理カメラ等が落ちていた。深度専用（`DEPTH_OUTPUT` かつ非BC）のみ除外し、それ以外は候補に含める。不可の use case は bind フォールバックとエラー通知で吸収する。
- **重複排除**: 論理カメラと同焦点の物理カメラが並んで 1x・2.5x 等が重複表示されていた。同一向き・種別・焦点（0.5mm バケット）を `dedupeLenses()`（純粋関数、単体テスト済み）で排除し、直接 bind 可を優先。
- **bind 三段フォールバック（写真系）**: preview＋静止＋QR解析 → preview＋静止 → preview のみ、の順に再試行。従来は一段失敗でカメラ死亡だった。静止 use case なしの bind ではシャッタータップ時に保存失敗を通知（無反応タップの解消）。
- **手動パネル堅牢化**: HAL が返す変形範囲（空・逆転・単一点・非有限）に `LabeledSlider` が `coerceIn`／`Slider` でクラッシュしうるため、範囲を正規化し、縮退時はスライダーなしの静的行を表示。
- **実機検証（Galaxy S24 SC-51E）**: 論理 0 背後の物理 2（超広角 f2.2）・6（望遠 f7.0）を認識、論理 0（f5.4・minFocus 10.0）が MACRO 誤分類されていたため閾値を 15 に修正。RAW12・HS 240fps を検出。手動パネルのクラッシュは `PreviewView` 単一インスタンスの二重 `AndroidView` ホストが原因と特定し、単一ホスト＋オーバーレイ方式に作り替えて解消。望遠撮影・スロー録画（240fps→8倍速保存）の保存を確認。プロ UI にレンズ切替ピルを追加。

## 物理カメラ対応・ISO原子性・プロUI（未リリース分）

- **物理カメラ列挙（Galaxy 望遠等）**: `cameraIdList` には論理カメラしか出ない端末向けに、`getPhysicalCameraIds()`（API 28+、それ未満は論理のみ）でサブカメラを列挙してレンズ化。`CameraLensInfo` に `logicalCameraId`（セレクタ一致用）＋`physicalCameraId`（`setPhysicalCameraId` 用、直接 bind 可は null）を追加。セレクタは論理 ID で一致させ、Preview／ImageCapture／VideoCapture の各 Builder に物理 ID を適用（API ガード付き）。物理側の特性（焦点距離・手動範囲・RAW・高速・絞り）で能力判定し、フラッシュ可否のみ論理側から継承（共有ユニットのため物理側は報告なし）。同一物理 ID の重複登録を排除し、論理→物理の順でソート。BG 録画サービスも `EXTRA_PHYSICAL_CAMERA_ID` で引き継ぎ。
- **ISO 原子性**：`ManualExposure.complete()` で露出の手動化を不可分に（片方設定→もう片方を既定値 ISO 100／1/60 で補完、片方 Auto→両方 Auto）。従来の半手動（AE OFF＋片側パラメータのみ）は HAL 未定義動作だった。UI の ISO・速度の Auto ボタンは `clearExposureManual()` に変更。EV 表示条件・プロファイルは従来どおり。
- **絞り値表示**：`LENS_INFO_AVAILABLE_APERTURES` を取得し、プロ UI のクイック行に F値表示（可変絞り制御は対象外、表示のみ）。
- **プロ UI（Sony 風）**：プロモード ON（写真・動画）で専用レイアウトに切替。黒背景＋縮小プレビュー、プレビュー上部に状態帯（バッテリー／モード／空き容量／焦点距離mm）、直下に SS・F値・EV・ISO クイック行（SS/ISO タップで手動化切替、EV タップで 0 リセット）、設定集中パネル（既存 `ManualPanel` をスクロール内包＋縦幅圧縮）＋シャッター。スマホ縦は上下、スマホ横は左右、タブレット縦は「プレビュー＋右端直下シャッター｜パネル」の 3 ペイン、タブレット横は左右。プレビュー面（`AndroidView`＋タップ／ピンチ＋装飾）は `PreviewSurface`／`PreviewDecor` に切り出して通常・プロ両経路で共用。通常 UI（非プロ）は従来のまま。パネル先頭にはアイコン行（手動終了・フラッシュ・タイマー等）を残し、プロ中も設定へ到達できる。
- **縮小プレビューの安全な実現**：`PreviewView` 単一インスタンスは単一 `AndroidView` ノードで保持し、外側 Box のサイズ（通常＝全画面、プロ＝設定アスペクトの小 Box）だけを切り替える。ノードの挿入・削除が起きないため二重ホストクラッシュが起きない。`ProModeOverlay` は透過スペーサ＋黒パネルのみ。S24 実機で縦横×通常／プロの全 4 配置＋設定画面の横配置を検証済み（プレビュー実測：縦 1080×810、横 1285×964 の 4:3）。

## 互換性ハードニング（v2.2.1: v2.2.0 リリース後の精査・修正）

多様な HAL・API 24〜36・センサ構成に対する精査で見つけた問題と修正:

- **F1 スロー bind のフォールバック**: 高 fps 要求（`CONTROL_AE_TARGET_FPS_RANGE`）を拒否する厳格な HAL では、従来は bind 全体が例外→カメラ死亡（プレビュー黒・シャッター無反応）だった。`bindVideoUseCases(useHighSpeed)` に切り出し、高 fps bind→失敗時は通常 bind に再試行する二段構えに。`Camera2Interop.Extender` が `VideoCapture.Builder` を受け付けられることは camera-camera2 1.5.0 の artifact（`ExtendableBuilder` 実装）で実確認済み。
- **F2 パノラマの JPEG 対応**: `YuvConverter` は YUV_420_888 のみ受理し、JPEG バインドの `ImageProxy`（単一プレーン）を無言で破棄していた。JPEG バイト列のデコード経路を追加し、回転適用を共通化。不明形式は従来どおり null（フレーム skip）。
- **F3 変換のスレッド移動**: フル解像度 YUV→JPEG 変換をメインスレッド（`OnImageCapturedCallback` 直下）で実行しており、高画素センサーで jank・ANR の恐れがあった。`Dispatchers.Default` の coroutine 内へ移動し、`image.close()` も同所で実施（close 前なら他スレッド利用は安全）。
- **F4 回転センサなし端末**: `TYPE_ROTATION_VECTOR` 不在では方位が来ず 1 枚目で停滞→終了時に破棄という詰みだった。センサ不在時は 2.5 秒間隔のタイマー撮影に切替（`FALLBACK_CAPTURE_INTERVAL_MS`）。
- **F5 パノラマのフラッシュ固定 OFF**: スイープ中に毎枚フラッシュが焚かれると露出がばらつき合成が壊れるため、PANORAMA bind は設定値によらず `FLASH_MODE_OFF`。
- **F6 低 RAM 適応**: `memoryClass <= 128` の端末ではフレーム幅 960px・最大 6 枚に縮小（`PanoEstimate.maxFrameWidth/maxFrames`、単体テスト済み）。通常は 1280px・8 枚。
- 精査で問題なしを確認した項目: 高速動画・RAW・露出補正・ズームの特性取得はすべて `detectLenses` の try/catch 内で実行（HAL の不正値でも検出全体が死なない）。`setOutputFormat` の RAW 要求は Camera2 側ゲート＋`takePicture` の onError 経路あり。DNG の MediaStore 保存は API 24〜28 でも動作（`RELATIVE_PATH` のみ Q+ ガード）。`MediaMuxer(path)` は API 18+ のため minSdk 24 で問題なし。RAW＋フラッシュの可否は HAL 依存のため失敗時はエラー通知（仕様として README に明記）。
- versionCode 8 / versionName 2.2.1。

## v2.2.0 の変更点（スローモーション・パノラマ・露出補正・スマホUI刷新・センサーRAW保存形式）

- **撮影モード追加**: `CameraMode` に SLOWMO / PANORAMA を追加（PHOTO / VIDEO / SLOWMO / PANO / OTHERS の5タブ）。OTHERS のスロー・パノラマ項目は未対応 Snackbar ではなく各モードへの遷移になった。マニュアルパネルは従来どおり PHOTO/VIDEO のみ（SLOWMO/PANORAMA/OTHERS では `setMode` で `isManualMode=false`）。
- **スローモーション**: レンズ検出時に `SCALER_STREAM_CONFIGURATION_MAP.highSpeedVideoSizes`＋`getHighSpeedVideoFpsRangesFor` から最良設定を取得（最高fps優先、同率なら最大面積）。`CameraMode.SLOWMO` は Recorder＋VideoCapture を HD/SD 優先で bind し、`Camera2Interop` で `CONTROL_AE_TARGET_FPS_RANGE=[maxFps,maxFps]` を preview/video 両ストリームに要求。録画停止後に `SlowMoProcessor` が MediaExtractor/MediaMuxer で映像トラックのタイムスタンプを `recordFps/30` 倍に引き伸ばして保存（再エンコードなし、音声は破棄）。対応機なし（maxFps < 60）の端末ではシャッター時に「未対応」Snackbar。minSdk 24 のため mux は一時ファイル経由（FileDescriptor 受けの MediaMuxer は API 26+）。
- **パノラマ**: `CameraMode.PANORAMA` は Preview＋ImageCapture（QR アナライザなし）で bind。シャッターでスイープ開始→回転ベクトルセンサの方位差が 12°以上（かつ前回から 1.2 秒以上）で自動撮影、最大 8 枚→終了で `PanoramaStitcher` が合成して保存。合成は並進のみ（重なり 30% のストリップで SAD 探索して垂直ずれ推定＋フェザーブレンド）。パノラマ中はピンチズーム無効（重なり前提が崩れるため）。2 枚未満では保存せず Snackbar。ガイド枠（両サイドのレール＋ヒント文）をプレビューに重ね、進捗（n / 8）と終了／キャンセルを下部バーに表示。
- **露出補正**: `CameraSettings.exposureCompensation`（EV インデックス、既定 0）を追加。検出時に `CONTROL_AE_COMPENSATION_RANGE` / `STEP` を取得し、AE 動作中（ISO・シャッター速度が両方 auto かつ AE_MODE_OFF でない）に `CONTROL_AE_EXPOSURE_COMPENSATION` を適用。マニュアルパネルでは露出が完全オートのときだけ速度スライダーの直下に EV スライダー（`label_ev`、`%+.1f EV` 表示、日英対応）を表示。全オートリセット・レンズ切替・プロファイル保存/読込にも EV を含めた。Room は v2 へ（`MIGRATION_1_2` で列追加、既存プロファイル保持）。
- **スマホ UI 刷新**: PHONE_PORTRAIT を下部シャッターバー構成に（サムネイル | 大シャッター 78dp | 前後切替）。ズームピルはズーム中のみ表示し、レンズ選択は広角基準の倍率ピル行（×0.5 / ×1 / ×2…、`LensZoomPills`）に。モード切替は中央寄せの横スクロールタブ（iPhone 風）。シャッター振り分けは `SharedActions.onShutter()` に集約（全レイアウト共通）。
- **タブレット空白の活用**: `SidePanelLayout` のパネル幅を `animateDpAsState`＋`animateContentSize` で可変に（通常 300dp、マニュアルパネル展開時は 460dp）。従来の `widthIn(max=380dp)` 固定を廃止。
- **センサーRAW保存形式**: レンズ検出時に `REQUEST_AVAILABLE_CAPABILITIES_RAW`＋`RAW_SENSOR` サイズで DNG 可否を判定（`RawCapability`）。ビット深度は `SENSOR_INFO_WHITE_LEVEL` のヒューリスティック（1023→RAW10、4095→RAW12、16383→API 37 の RAW14）を UI バッジ専用に保持。`SaveFormat`（JPEG / JPEG+RAW / RAW）をプロモードのマニュアルパネル先頭で選択（対応レンズのみ、非対応は JPEG 固定）。撮影は CameraX 1.5 の `setOutputFormat(OUTPUT_FORMAT_RAW / RAW_JPEG)` を使用し、PHOTO かつ OS 要求なしの場合のみ RAW 系を要求（パノラマ・OTHERS・外部要求は JPEG 固定）。JPEG+RAW は二重コールバックを MIME 判定で振り分け、DNG は `Pictures/Fcam pro` に `.dng` で保存。
- versionCode 7 / versionName 2.2.0。単体テスト 18 件（EV クランプ・表示、スロー倍率、方位差、合成のずれ推定・幅合成、RAW 深度・形式フォールバックを含む）＋ lint グリーン。

## v2.1.0 の変更点（ズームUI・起動時1倍保証・バックグラウンド録画の安全性）

- **ズームUI表示**: 操作パネル上部に現在のズーム倍率ピルを追加（`ZoomPill`）。ズーム対応レンズ（maxZoom > 1）のときのみ表示。ズーム中は強調色＋太字、タップで 1.0x にリセット（UI 状態と `cameraControl.setZoomRatio(1f)` の両方）。日英完全対応（`zoom_ratio` / `cd_zoom_reset` を `values/` と `values-ja/` に追加）。
- **起動時ズーム初期化の保証**: bind 成功後に `zoomRatio = 1f`＋`maxZoomRatio` 更新＋`setZoomRatio(1f)` を明示実行。従来はローカル状態のみ 1f に戻しており、`ProcessCameraProvider` が同一 `Camera` インスタンスを返す場合にレンズ側ズームが残留する論理ミスがあった（UI は 1.0x 表示なのに画角がズームされたまま）。ピンチ上限は bind 直後の `zoomState.maxZoomRatio` を保持し、ジェスチャ時は `ZoomRatios.next()`（単体テスト済み）でクランプ。
- **バックグラウンド録画の安全性**:
  - 連続タップの二重起動ガード（`startPending`＋`removeCallbacksAndMessages`）。従来は 350ms 以内の 2 回目の start が 2 つ目の bind をキューし、`recording` を上書きして 1 つ目の `Recording` をリークした。
  - FGS タイプを用途別に（起動時は CAMERA のみ、音声あり録画時のみ CAMERA|MICROPHONE）。従来は常時 MIC 付きで、音声なし設定・マイク権限なしの端末では Android 14+ で起動失敗した。
  - 使用中のレンズ ID と画面回転を引き継ぎ（`EXTRA_CAMERA_ID` / `EXTRA_TARGET_ROTATION`、対応不可時は従来の前面/背面既定にフォールバック）。従来は望遠・マクロ選択中も広角既定に戻っていた。
  - 通知 largeIcon をキャッシュ（毎秒 `decodeResource` していたメモリ churn を解消）。`ExperimentalCamera2Interop` の OptIn をサービスクラスに付与（lint エラー解消）。
- **録画中の誤操作防止**: BG 録画中はシャッター・レンズ切替を無効化（`camera == null` のため無反応だったタップに明示の disabled 表示）。外部キャプチャバーも同様。`capturePhoto` / `toggleRecording` に `bgRunning` ガードを追加。
- **表記統一**: OTHERS の「Bg record / 背面録画」を「BG record / BG録画」に（「背面」はリアカメラと紛らわしいため）。
- 破壊的変更なし。versionCode 5 / versionName 2.1.0。

## v2.0.0 の変更点（操作パネルの再設計）

3 つのレイアウトを画面サイズ・向きで自動選択（`smallestScreenWidthDp` と `orientation`）:
- **PHONE_PORTRAIT**（<600dp・縦）: 従来のスマホ用の縦積み UI。上部にアイコン行、下部に操作。
- **LARGE_PORTRAIT**（≥600dp・縦）: 画面**左**に浮くパネル。アイコン群は 2 列（二段）、PHOTO/VIDEO/OTHERS は縦タブ。パネルの位置を「上／中央／下」に寄せられ、影（スクリム）はパネルの内容がある範囲だけ（`wrapContentHeight`）。OTHERS は 2 アイコン/行で段が増える。
- **SIDE**（横向き全般）: 画面**右**のサイドバー（全高スクロール）。

共通:
- パネルは下部のボタンで開閉できる（`AppSettings.panelCollapsed` に永続）。閉じると、フロント/バック切替＋シャッター＋「開く」ボタン＋バッテリー残量だけの小さなクラスタが残り、ドラッグで移動可能（画面外に出ないようクランプ）。撮影モードは保持。
- **マニュアル設定を開くボタン（Tune/AutoMode）は PHOTO/VIDEO のときだけ表示。** OTHERS に切り替えた時点で `isManualMode=false`（`CameraViewModel.setMode`）。
- **フロント/バック切替はシャッターボタンの横**（全レイアウト）。上部アイコン行からは撤去。
- **設定アイコンは常時表示**（上部アイコン行の末尾）。
- レンズ切替（超広角/広角/望遠/マクロ/前面）は、対応レンズが 2 つ以上あれば丸ボタンの行として**常時表示**（録画中は無効）。ポップアップは廃止。
- マニュアル撮影パネルから**シャッター音量スライダーを撤去**（シャッター音は設定画面のトグルのみ）。
- 操作パネルの下部に**最新の撮影サムネイル**（実画像/動画フレームを 160px で読込。無ければアイコン）。タップで標準ギャラリーへ。
- バッテリー残量: `ACTION_BATTERY_CHANGED` を `RECEIVER_NOT_EXPORTED` で購読。パネルを閉じたときはシャッターの下に表示。
- ランチャーアイコンを新しい 256px 画像から再生成（全 density、square + round）。

versionCode 4 / versionName 2.0.0。

## v1.0.2 の変更点（安定性・確実性・ドライバ認識・メモリ安全性・UI 完全性の精査）
- **ドライバ認識 / ANR**: カメラ列挙 `detectLenses` をメインスレッドから `Dispatchers.Default` へ。ViewModel 生成時に camera HAL 初期化でメインスレッドが止まらない。`noCameraAvailable` を `StateFlow` 化し、検出完了時に UI へ反映。
- **UI 完全性 / 安定性**: 画面回転で Activity を再生成しない（`android:configChanges`）。プレビュー中断・ローカル状態喪失・黒画面フラッシュを防止。回転時の写真/動画の向きは `DisplayManager.DisplayListener` で `imageCapture/videoCapture.targetRotation` を更新して維持。
- **メモリ安全性**: 写真↔動画モード切替時に旧 `ImageCapture` 参照を null 化、`ImageAnalysis` と ML Kit `BarcodeScanner` を確実に `release()`。QR 解析は専用の単一スレッド `Executor` で実行し、画面破棄時に `shutdown()`。
- **動作の確実性**: ピンチズーム上限を CameraX の `cameraInfo.zoomState.maxZoomRatio` から取得（Camera2 のデジタルズーム最大値ではない）。ズーム比 1.0 のパンジェスチャは無視。
- セルフタイマー中にシャッターを再タップでカウントダウンをキャンセル可能。タイマー `Job` は画面破棄時にキャンセル。
- フォーカスレティクルを `onSizeChanged` で得たプレビュー領域内にクランプ（端タップで枠がはみ出さない）。
- ギャラリーボタンの「最後の撮影」を ViewModel 保持 → 設定往復後も維持。外部 `ACTION_IMAGE_CAPTURE`（`EXTRA_OUTPUT` なし）の返却サムネイルを 1024px 以下へダウンサンプル（`TransactionTooLargeException` 回避）。
- `MainActivity.onNewIntent` 対応 — 起動中に他アプリから `IMAGE_CAPTURE`/`VIDEO_CAPTURE` が来ても取りこぼさない。
- `BackgroundCameraService`: `onCreate` で `running` フラグをリセット（前インスタンス異常終了からの復帰）、`onDestroy` で保留中の Handler コールバックを除去。
- versionCode 3 / versionName 1.0.2。

## 3. 既知の制約（v2.5.1 時点）

- バックグラウンド録画は画面オフ・Home・履歴削除後も継続するが、OSの強いメモリ／電力制約下での無制限継続は保証しない。
- スローモーションは端末の constrained high-speed video が 60fps 以上の場合に利用でき、保存時に音声を除いて30fps基準へ時間伸長する。パノラマは平行移動推定＋フェザーブレンドのため、強い視差では継ぎ目が出る場合がある。
- 論理マルチカメラの背後に隠れた物理サブカメラは個別選択できない場合がある。
- Xperia 1 SOV40 と Galaxy S24 SC-51E で主要経路を確認済み。全メーカー・全 HAL 構成の網羅はしていない。
- シャッター音は MediaActionSound の再生有無のみ制御（Android の仕様上、細かな音量制御・強制音の抑止は不可）。
